## 1. The AI Trust Architecture (my suggestions, baked into every page)

Trust in an AI advisor is designed, not claimed. Five mechanisms:

1. **Show the machine openly.** A signature exhibit "How the twin thinks" — inputs drawn as sources feeding a engine: your 3 books + 20 years of work → your thinking → a plain answer. Includes an honest boundary box: what it is (your frameworks), what it is not (not legal advice, not ChatGPT, no flattery). Honest AI disclosure *raises* trust.
2. **Proof before asking.** Sample conversations as "Field Record" exhibits — real question → twin's answer, rendered as transcript panels. The owner reads one answer and thinks "this thing is sharp."
3. **A named human behind it.** Your face, name, credentials (IIM-C, IICA, 3 books) adjacent to every chat entry point. AI + named accountable human = trust.
4. **A visible escalation path.** The drawn funnel: Ask the twin (free) → solution document in 72 hours → paid execution. The AI is intake, never the end of the road — SME owners trust AI as a door, not a destination.
5. **Privacy honesty.** Plain-language "what happens to your conversation" note near every chat box (DPDP-friendly, no legalese).

**Machine trust too** (so AI search engines recommend you): rich JSON-LD (Person, FAQ, Service), `llms.txt`, semantic HTML, fast loads, valid markup — the site reads cleanly to both humans and AI crawlers.

## 4. Engineering — latest tech, best practices, zero bloat, hardened

**Modern static stack (no frameworks = no bloat):** semantic HTML5 (`header/nav/main/section/article/figure`), modern CSS (custom properties, `oklch()`, `clamp()`, grid, `:has()`, `prefers-reduced-motion`, container queries where useful), modern JS as **ES modules** (`assets/hk.js`: IntersectionObserver reveals, `<dialog>` FAQ panels, tabs, seats, tooltips, motion toggle, chat). No build step, no CDN framework, no duplicated scripts (today's ~90-line chat script is copy-pasted twice — becomes one module).

**Readable by anyone:** consistent naming, one purpose per function, JSDoc-style comments explaining *why* where non-obvious, sectioned and commented CSS, logical file order, valid W3C markup, correct heading hierarchy, full ARIA.

**Cybersecurity:**
- Strict **CSP** (`script-src self`, style/font/img origins pinned to self + Google Fonts, `connect-src` pinned to the Cloud Run endpoint) — enforced via meta + a ready `_headers` file for your host.
- **XSS-safe chat rendering:** self-hosted marked.js + **DOMPurify** sanitization of every twin reply before it touches the DOM (today's code renders raw HTML — a real XSS hole), input length limits, no inline event handlers.
- Self-hosted libraries with **SRI** hashes; `rel="noopener noreferrer"` + `referrerpolicy` on external links; HTTPS-only; no secrets in client code; conversation data handling documented per DPDP.

**Trust plumbing:** JSON-LD (Person, FAQPage, Service), `llms.txt`, sitemap, descriptive `<title>`/metas, local assets only, single accent token, no dead links (About + People Development ship real).
